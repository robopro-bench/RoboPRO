Installation

Install.

Seven steps from a clean checkout to a first headless rollout.

← Home Code ↗

Step 1 · Clone

Clone the repository with its submodules.

git clone --recurse-submodules https://github.com/robopro-bench/RoboPRO.git
cd RoboPRO

policy/pi0/openpi and policy/pi05/openpi are git submodules of openpi, needed only for the π0 / π0.5 policies. If you cloned without --recurse-submodules, run git submodule update --init policy/pi0/openpi policy/pi05/openpi.

Step 2 · System

System packages.

RoboPRO needs Vulkan, ffmpeg, uv, and the CUDA toolkit (nvcc) at the OS level:

sudo apt install libvulkan1 mesa-vulkan-drivers vulkan-tools ffmpeg
vulkaninfo           # smoke test
make check-prereqs   # checks uv, git, nvcc, ffmpeg

An NVIDIA driver with CUDA 12.x is required (torch==2.4.1 from PyPI targets CUDA 12.1).

Step 3 · uv env

Create the .venv.

uv venv --python 3.10
source .venv/bin/activate
export PYTHONNOUSERSITE=1

The PYTHONNOUSERSITE step matters: without it, a prior ~/.local/lib/python3.10/site-packages/sapien (or torch) can be picked up ahead of the project's environment and break imports.

Step 4 · Python deps

Install Python deps and CuRobo.

make bootstrap   # same as: bash scripts/install/bootstrap_uv.sh

bootstrap_uv.sh syncs .venv from the root pyproject.toml and uv.lock, patches sapien/wrapper/urdf_loader.py (utf-8 encoding) and mplib/planner.py (drops a too-strict collision check), then clones CuRobo v0.7.8 into sim/envs/curobo/ and installs it editable. It re-pins warp-lang==1.12.0 and setuptools==69.5.1 at the end. CuRobo pulls in scikit-image, which upgrades scipy past the 1.10.1 pin; that is expected, so do not re-pin it afterwards.

The benchmark is pinned to sapien==3.0.0b1. Other SAPIEN versions change physics and rendering, so their success rates are not comparable. PyPI has no aarch64 wheel for it; on ARM machines build it from source with docs/setup_sapien_aarch64.md.

Step 5 · Assets

Fetch the asset bundle (~15 GB).

make download-assets   # same as: python scripts/install/download_assets.py

Pulls the HuggingFace asset bundle (repo id in scripts/install/download_assets.py) into repo-root assets/ (objects, embodiments, background_texture, backgrounds). The bundle already includes aloha-agilex/.../meshes/box2_Link.dae (~206 MB), so no separate fetch is needed. To keep the assets elsewhere, download with make download-assets ASSETS_DEST=/path and then run make link-assets ASSETS_DEST=/path.

Generate the local-path CuRobo configs from the shipped templates, and patch them so CuRobo can attach grasped objects (the shipped configs lack the attached_object link entries):

make configure-curobo-assets
make patch-curobo-config   # same as: python scripts/install/patch_aloha_curobo.py

Step 6 · CuRobo cache check

Check clear_cache (no edit needed on v0.7.8).

WorldMeshCollision.clear_cache must reset _env_mesh_names between episodes, or stale collision meshes leak across rollouts. CuRobo v0.7.8, the version the install pins, already does this upstream. Verify with:

sed -n '/def clear_cache/,/super().clear_cache()/p' \
    sim/envs/curobo/src/curobo/geom/sdf/world_mesh.py

Only if you pin a different CuRobo version whose clear_cache lacks that reset, replace the method with:

def clear_cache(self):
    self._wp_mesh_cache = {}
    if self._mesh_tensor_list is not None:
        self._mesh_tensor_list[2][:] = 0
    if self._env_n_mesh is not None:
        self._env_n_mesh[:] = 0
    if self._env_mesh_names is not None:
        self._env_mesh_names = [
            [None for _ in range(self.cache["mesh"])] for _ in range(self.n_envs)
        ]
    super().clear_cache()

Step 7 · Verify (headless)

Run one rollout.

cd sim
source ../set_env.sh

python script/bench_script/visualize_task_scene.py \
    put_mouse_on_pad bench_demo_office_clean \
    --bench-subdir office --rollout --no-render --seed 0 --save_data

From the repo root, make verify-rollout runs the same rollout. On success you'll see Success: True and an MP4 at repo-root data/video/episode_put_mouse_on_pad_0.mp4 (~176 frames at 320x240, ~6 s). Drop --no-render --save_data to use the interactive SAPIEN viewer instead.

Data collection and policy evaluation are covered in the README.
